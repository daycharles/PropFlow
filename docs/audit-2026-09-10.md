# Code + security audit — 2026-09-10

Scope: the whole `develop` tree at the M3 promotion (`b31b864`) plus everything added since —
the M3 vertical slice (`daycdev`), M6 assets, global search (PF-6.08), the Integrations module
(PF-6.10). Supersedes the open items in [`audit-security.md`](audit-security.md) where noted.

**No Critical or High findings. No working cross-tenant data path.** Tenant isolation holds on
all 15 business tables across the four schemas — forced RLS + `tenant_isolation` policy + org
FK + EF query filter + `GuardWrites`, verified by the integration suite against real
PostgreSQL. `dotnet list package --vulnerable` is clean; `apps/web` now has a committed
lockfile and runs `npm ci` / lint / build / Playwright in CI.

Status: **fixed** (this change), **open** (recorded, deferred).

## Fixed in this change

### A-1 — Terminal work could be reopened through `PUT /api/work/{id}` (Medium)

`WorkItem.ChangeStatus` and (as of PF-3.27) `AssignVendor`/`AssignEmployee` refused
`Completed`/`Cancelled` work, but `Edit` and `Schedule` did not. `Schedule` sets
`Status = Scheduled` unconditionally, so a `Work.Update` caller who sent a `scheduledStart` for
a completed item silently un-completed it (leaving a stale `CompletedAt`), bypassing the
`ChangeStatus` guard.

**Fix:** `Edit` and `Schedule` now call `RefuseWhenTerminal()`. `PUT /api/work/{id}` on
terminal work is a 400 in full (the endpoint always calls `Edit`). Covered by
`WorkItemTerminalStateTests` and `Updating_terminal_work_returns_400_and_cannot_reopen_it`.

**Follow-up (PF-4.07):** `SetPriority` also gained the guard, and `WorkItem.Reopen(actorId, at)`
was added as the *one* sanctioned exit from a terminal state (moves to `Assigned`/`New`, clears
`CompletedAt`, raises `WorkReopened`), surfaced only via `POST /api/work/bulk/reopen`. The
invariant is now "terminal, except through `Reopen`" — see `.claude/rules/traps.md`.

### A-2 — Work-list search did not escape `LIKE` metacharacters (Low)

`EfWorkOperations.ListAsync` interpolated the raw term into `ILIKE '%term%'`. Not SQL
injection (EF parameterizes the value) but `_` and `%` acted as wildcards and forced a full
scan. `EfGlobalSearch` already escaped correctly; the work list did not.

**Fix:** escape `\ % _` and pass an explicit `ESCAPE '\'`, matching `EfGlobalSearch`. Covered
by `Work_list_search_treats_like_metacharacters_literally`.

### A-3 — Saved views had no size or count limit (Medium, DoS)

`SavedView` validated `filters`/`columns` as JSON but not length, and the endpoint set no
per-user cap. Any `Work.Read` user could store many multi-MB blobs (bounded only by the ~30 MB
request limit), each returned on every `GET /api/saved-views`.

**Fix:** `SavedView.MaxDefinitionLength = 8 KB` per definition; the create endpoint rejects a
101st view per user with 409. Covered by `An_oversized_view_definition_is_rejected`.

### A-4 — Unbounded lookup-list responses (Low)

`/api/vendors`, `/api/employees`, `/api/properties`, and the buildings/spaces in
`/api/properties/{id}` returned every row with no cap (`/api/assets` already used `Take(500)`).
`EfIntegrationOperations.RecordsAsync` likewise returned every tracked external record.

**Fix:** `Take(500)` on all of them. A tenant that outgrows this needs a paged endpoint (noted
below).

## Open

### M-1 — `identity` schema has no row-level security (Medium) — still open

Unchanged from `audit-security.md`. `Memberships` / `Organizations` carry no RLS and the
runtime role holds `SELECT ON ALL TABLES IN SCHEMA identity`. Not exploitable today (no
listing endpoint; `MembershipAccess` methods are scoped) but the login flow reads a user's
memberships *before* a tenant context exists, so a naive org-scoped policy would break sign-in.
Needs a design pass before any member-list / invitation endpoint.

### A-5 — Work create/update accept unvalidated child ids (Low) — fixed

**Fix (audit follow-ups PR):** `EfWorkOperations.EnsureChildReferencesAsync` checks
`BuildingId` / `SpaceId` / `CategoryId` / `ResidentId` (each through the tenant query filter) on
both create and update; a missing or foreign id is a 400. `UpdateAsync` also gained the
`PropertyId` existence check `CreateAsync` already had, and the `PUT` endpoint now maps
`KeyNotFoundException` to 404. Covered by
`Creating_or_updating_work_rejects_a_child_reference_outside_the_tenant`.

### A-6 — Lookup lists are unpaged (Low) — partly fixed

**Fix (audit follow-ups PR):** `/api/integrations/{id}/records` now takes `?page=` / `?pageSize=`
(1–200) and returns `{ items, totalCount, page, pageSize }`. `/api/vendors`, `/api/employees`,
`/api/properties` keep the flat-array shape the web client depends on but gained an optional
`?q=` name filter (still capped at 500). Full offset paging for those three is deferred until
they get dedicated screens — a coordinated web change (`docs/followups.md`).

### A-7 — Trigram similarity branch in global search is not index-backed (Medium, perf) — fixed

**Fix (audit follow-ups PR):** `EfGlobalSearch` now wraps its queries in one transaction, sets
`pg_trgm.word_similarity_threshold = 0.25` with `SET LOCAL`, and filters with
`EF.Functions.TrigramsAreWordSimilar` (`q <% col`) instead of `word_similarity(...) >= 0.25`.
`<%` rides the `gin_trgm_ops` index; `word_similarity()` is kept only for the score/ranking. The
0.25 threshold and recall are unchanged — `Tolerates_a_spelling_variant_via_trigram_similarity`
still passes.

### Carried forward unchanged

L-1 (session-scoped tenant GUC), L-2 (unused `DELETE` grants — now also `WorkItems` only, plus
none on the integrations tables), L-5 (null-IP rate-limiter bucket), and the deferred
Communications items (C3/PF-7.05). `ValidateTimeZone` still accepts any `x/y` string rather
than a real IANA zone — folded into PF-7.04.

## Resolved since the last audit (verified)

- **M-3** `apps/web` lockfile + CI — `package-lock.json` committed; CI runs `npm ci` / format /

## Second pass — 2026-09-10 (PF-4.07 bulk actions + A-5/A-6/A-7 review)

Audit of the new surface: `WorkItem.Reopen`/`SetPriority`, `BulkApplyAsync` + the five
`/api/work/bulk/*` routes, `EnsureChildReferencesAsync`, the paged `RecordsAsync`, the `?q=`
lookup filters, and the `EfGlobalSearch` `<%` rewrite. **No Critical or High. No cross-tenant
path** — every bulk query loads through the tenant filter + RLS, and a foreign id in a batch
makes the whole batch a 404.

### Fixed in this pass

| | Severity | |
|---|---|---|
| **B-1** | Low (DoS/500) | A `null` element in a bulk `items` array dereferenced to a `NullReferenceException` → 500. `ValidBatch` now rejects a batch containing a null entry or an empty `workId` — for the new routes **and** the pre-existing `bulk/vendor`. |
| **B-2** | Low-Med (integrity) | `bulk/note` set the per-item version as `OriginalValue` but a note insert doesn't touch the work row, so a stale version passed silently — contrary to the "per-item concurrency check" contract. `BulkApplyAsync` now compares every item's loaded `xmin` to the client version up front and returns 409 on any mismatch (covers all five actions). |
| **B-3** | Low-Med (integrity) | `System.Text.Json`'s `JsonStringEnumConverter` also accepts integers, so `{"status": 999}` deserialized to `(WorkStatus)999` and `ChangeStatus` stored it as the string `"999"`. `Enum.IsDefined` guards added to `bulk/status`, `bulk/priority`, **and** the pre-existing `POST`/`PUT /api/work` (work type / priority / status). |
| **B-4** | Low | `bulk/schedule` re-scheduling an item to the window it already had wrote a redundant `Scheduled` timeline entry and counted it as `changed`. `ApplyOne` now skips a true no-op, matching `UpdateAsync`. |
| **B-5** | cosmetic | Dead `const double Threshold` in `EfGlobalSearch` after the `<%` rewrite removed every `>= Threshold` comparison — removed. |

Tests: `A_bulk_note_still_honours_the_per_item_version`, `A_null_item_or_an_undefined_enum_is_a_400`,
`Re_scheduling_to_the_same_window_is_a_no_op` (integration).

### Verified sound (no finding)

- **`WorkItem.Reopen`** is the only method that leaves a terminal state; it requires
  `IsTerminal`, a non-empty actor, clears `CompletedAt`, and raises `WorkReopened`. `Edit`,
  `Schedule`, `SetPriority`, `ChangeStatus` and both assignment overloads all still call
  `RefuseWhenTerminal()`. `.claude/rules/traps.md` records the invariant.
- **`BulkApplyAsync`** runs in one transaction; assignability is checked for the whole batch
  before any mutation (one terminal item, or one un-assigned item for `schedule`, or one live
  item for `reopen`, refuses the batch); `DbUpdateConcurrencyException` rolls back and reports
  `Conflict` with nothing written.
- **A-7 `<%` rewrite** — with `SET LOCAL pg_trgm.word_similarity_threshold = 0.25`, `q <% col`
  is exactly `word_similarity(q, col) >= 0.25`, i.e. identical recall to the old code, and `<%`
  is accelerated by the existing `gin_trgm_ops` indexes. The `SET LOCAL` is scoped to the
  search's own transaction and reverts on commit/rollback. RLS still applies inside the
  transaction (`Search_is_confined_to_the_current_tenant` passes).
- **A-5** — `EnsureChildReferencesAsync` checks each ref through the tenant query filter, so a
  foreign id reads as "not found" → 400. `UpdateAsync` gained the same `PropertyId` check
  `CreateAsync` had; `PUT` maps `KeyNotFoundException` → 404.

### Open (recorded in `docs/followups.md`)

| | Severity | |
|---|---|---|
| **B-6** | Low | Child refs are validated for existence but not hierarchy — a work item may name Property A with a Space that belongs to Property B (same tenant). `SetLocation` doesn't enforce it either. Needs a `SpaceId`→`PropertyId` (and building) consistency check. |
| **B-7** | Low | A bulk `WorkNote` carries an `internal`/`resident` marker but nothing enforces resident-visibility on reads yet — that is PF-5.06. The note text has no control-character guard (it renders in the React timeline, which escapes). |
| **B-8** | Low | `?q=` on `/api/vendors|employees|properties` has no length bound (the result is still `Take(500)`-capped). |
| **B-9** | Low | `WorkReopened.EventId` is generated then discarded (the timeline entry gets its own id via `Event()`), and `Reopen` on a never-published Draft→Cancelled item leaves `CreatedAt` at `default` — ties into the existing `CreatedAt`-only-in-`Publish` debt. |

## Third pass — 2026-09-10 (TimelineEntry #107 + resident messages #108)

Audit of the new surface: the finished `TimelineEntry` generalization (PR #107), and
`POST /api/work/{id}/message` + the timeline's cross-context message merge (PR #108).
**No Critical or High. No cross-tenant path** — every lookup in the send endpoint and both
sides of the timeline merge go through a tenant-filtered `DbSet`; a foreign `workId` or
`templateId` is a 404.

### Fixed in this pass

| | Severity | |
|---|---|---|
| **C-1** | Medium | `POST /api/work/{id}/message` built its outbox idempotency key from a fresh `Guid`, so the outbox's built-in de-dup never fired — an accidental double-submit queued the resident **two** messages, and the `202` body said `queued: true` even when nothing was queued. Now keyed `work-message:{workId}:{templateId}:{channel}:{yyyyMMddHH}` (a double-click within the hour is one message; a deliberate re-send an hour later still goes through), and the response reports the real `EnqueueAsync` result. Test `A_double_submit_of_the_same_template_is_deduped`. |
| **C-2** | Low | No test that a control character reaching a **rendered** email subject (`{{ work.title }}` in the subject, a work title carrying a CRLF) is rejected. `OutboxMessage.Create` → `MessageText.RequireSingleLine` already backstops it as a 400 and nothing is enqueued; added `A_control_character_reaching_a_rendered_email_subject_is_a_400` to lock it in. |

### Verified sound (no finding)

- **TimelineEntry (#107)** — one shape, no event-specific columns. `From(VendorAssigned)` /
  `From(EmployeeAssigned)` / `From(WorkReopened)` all route through `WorkEvent(...)`, which fills
  `EventType` / `OldValue` / `NewValue` / a `{oldValue,newValue}` `Changes` JSON. The dead
  `Create(...)` is gone; `20260910122538_TimelineDropLegacyVendorColumns` is a plain
  nullable-column drop (the same before/after is preserved in `OldValue`/`NewValue`).
- **`TimelineAsync` merge** — reads `store.Timeline` and `comms.OutboxMessages` (both
  tenant-filtered), maps to `TimelineItem`, sorts in memory. It is **read-only** — there is no
  cross-context write, so the C11 atomicity concern does not apply. Confirmed by
  `Api_filters_reads_and_conceals_foreign_work_and_timeline` and `ResidentMessageTests`.

### Open (recorded in `docs/followups.md`)

| | Severity | |
|---|---|---|
| **C-3** | Low | `GET /api/work/{id}/timeline` now surfaces the resident's phone/email (as the message recipient) in `MessageQueued`/`Sent` entries to any `Work.Read` viewer. Consistent with `/api/residents` already exposing contact info at `Work.Read` — not a new class of exposure, but worth tightening when the resident-visible timeline (PF-5.06) lands. |
| **C-4** | Low | The timeline endpoint is unpaginated (as it was before #108). A work item with hundreds of history entries returns all of them plus all its messages. |
| **C-5** | Low | `WorkItem.Required` (title) does not reject control characters, unlike `Resident.FullName` (`MessageText.RequireSingleLine`). Harmless for the message path (the `OutboxMessage` guard catches it) but an inconsistency in the domain. |

## Fourth pass — 2026-09-10 (PF-4.10 Tidewater demo seed, #114)

Audit of the one new file, `tools/PropFlow.Admin/TidewaterSeed.cs` — the deterministic demo
dataset generator wired into `seed-demo` for the primary org. **No Critical / High / Medium. No
security surface** — it is an admin-only, `ConnectionStrings__Admin` seeding path that runs once
per empty org; it takes no external input and touches no tenant-facing code. Every finding is
data-quality or code-clarity. All fixed in the same PR (#115); each verified against a real
PostgreSQL 17 with `seed-demo` re-run and the row counts queried.

### Fixed in this pass

| | Severity | |
|---|---|---|
| **D-1** | Low | A `Completed` item's close timestamp was drawn independently of its publish timestamp — `ChangeStatus(Completed, now - 1..20d)` against `Publish(now - 1..30d)` — so ~⅓ of completed demo items had `CompletedAt` **before** `CreatedAt` (a negative time-to-close). Now the item's `reportedDaysAgo` is drawn once and completion is `reportedAt + 1 .. reportedDaysAgo` days — always after the report, always in the past, no clamp. Query `CompletedAt < CreatedAt` → 0. |
| **D-2** | Low | The 6 "prior tenancy" occupancies used an unrelated random date window, so a prior (ended) occupancy could overlap the **current** occupancy of the same space — "who lived at space X on date D" would return two people. Prior tenancies are now anchored to end 1–12 months **before** the current resident moved in. Self-join overlap query → 0. |
| **D-3** | Low | Overdue open items got a due date in an absolute `now - 1..13d` window, independent of `reportedAt`, so a freshly-reported item could be "due" before it was reported. Overdue due dates are now `now - rng.Next(1, reportedDaysAgo)` — strictly between the report and now. |
| **D-4** | Trivial | Dead code: a "guarantee ≥ 20 pest-control items" loop that could never execute — the round-robin over 23 templates (first 6 pest) already yields exactly 30 of 100. Removed; the count is now stated in a comment and asserted by query (`= 30`). Doc counts corrected from "~20" to "30". |
| **D-5** | Trivial | The consent-distribution comment said "~55% both" — the code produces ~55% **SMS-only**, ~20% both, ~10% email-only, ~15% none (verified: 38 / 15 / 8 / 9 of 70). Comment corrected. |
| **D-6** | Trivial | `Slug()` collapsed only doubled separators (`String.Replace("--","-")` leaves `---` as `--`), so `"Harbor HVAC & Refrigeration"` produced the email `dispatch@harbor-hvac--refrigeration.example.test`. Rewritten to `Split('-', RemoveEmptyEntries)` + `Join`. Now `dispatch@harbor-hvac-refrigeration.example.test`. |
| **D-7** | Trivial | Redundant `assetsByProperty` local recomputed the property-id list already built as `propertyIds`. Removed. |

### Verified sound (no finding)

- **Status pipeline** — `AssignVendor`/`AssignEmployee` only move `New → Assigned`, so every
  `switch` arm reaches its target status through the domain's own transitions
  (`Publish → [Assign] → ChangeStatus/Schedule`). Seeded row counts match `BuildStatusPlan`
  exactly (5/16/15/12/12/8/22/10). No `ScheduledEnd < ScheduledStart` (the single-`slot`
  fix holds).
- **Idempotency** — `if (await store.WorkItems.AnyAsync()) return;` guards a re-run; the
  isolation org keeps its own minimal `SeedOperationsAsync`. `seed-demo` run twice is a no-op
  the second time.
- **Determinism** — one `new Random(20260410)` threads the whole method; `BuildStatusPlan`'s
  separate `new Random(11)` is intentional and fixed. Re-running the seed on a fresh DB
  reproduces identical counts.
- **Domain guards** — every value the seed feeds in (`Occupancy.EndOn` ordering, `Asset.SetLifecycle`
  service-life range and warranty-after-install, `SetReplacementCost`/`SetCost` non-negative,
  `Resident`/`Vendor` single-line contact fields) satisfies the constructor/method invariants;
  the seed threw on none of them and the CI `e2e` job runs `seed-demo` against real Postgres.

### Open

None. The isolation-org seed (`DemoSeeder.SeedOperationsAsync`) still publishes its 12 items at
`now` with due dates `now - 3d … now + 8d`, so 2 of them are "due before created" — pre-existing,
out of scope here, and harmless for its only purpose (tenant-isolation checks).
